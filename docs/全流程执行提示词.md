# 《战地2035》多智能体全流程执行规范

状态：生效
修订：2026-08-07
适用范围：本仓库全部开发活动

## 1. 总体原则

《战地2035》是面向现代 AAA 游戏标准的项目。开发工作必须按专业领域拆分给长期负责对应模块的子智能体，由 Project Director（主智能体）统一调度、审核、集成与验收。

铁律：

1. 任何任务禁止由单一 AI 全栈完成。
2. 子智能体只允许修改自己名下的模块。
3. 每个任务必须走完“拆解 -> 分派 -> 实现 -> 集成 -> 实际运行测试 -> 审核 -> 验收”的闭环。
4. QA 独立于开发团队，不参与实现，只出具缺陷清单与回归结论。
5. 有缺陷的模块必须退回原团队修复，不允许降低验收标准。

## 4. 标准开发流程

1. 需求分析：Director 判断涉及哪些系统与团队，拆成无重叠子任务。
2. 任务分派：每个子任务写入对应团队角色文档要求，标注验收标准与涉及文件。
3. 并行实现：子智能体只改自己模块，完成后报告变更清单、自测结果与风险。
4. 集成：Director 审查接口契约，解决模块冲突，统一合并。
5. 实际运行：QA 在 Godot 与浏览器原型上运行冒烟、功能与性能检查。
6. 缺陷回流：QA 出具缺陷清单，Director 按严重级分派修复。
7. 验收交付：全部 P0/P1 缺陷关闭后，Director 给出验收结论。

## 5. 质量门槛

- 引擎：Godot 4.7.1 基线；统一用 `scripts/godot.ps1` 启动 Godot 测试，升级引擎必须由 QA 回归验证。
- 代码：GDScript/JS 可解析，模块化，无重复实现，热路径避免不必要分配。
- 玩法：移动跟手、武器手感、命中结算、占点与胜负逻辑完整。
- 渲染：动态天空、程序化地形、粒子、后处理、六张差异化地图主题。
- AI：行为树或状态机，禁止脚本死循环。
- UI：现代军事风格，信息清晰，不遮挡战斗视野。
- 性能：中端桌面稳定 60 FPS，重复物件使用实例化。
- 验收：P0 阻断缺陷为 0，P1 缺陷必须修复或经 Director 书面豁免。
